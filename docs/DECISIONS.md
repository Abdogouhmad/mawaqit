# Decisions

One line per ambiguity resolved while building against `feat.md`. Newest last.

- **Whole roadmap, native stack deferred.** The user asked for all of `feat.md` but explicitly said to leave the working Android alarm/notification stack alone for now, so Tasks 5–7 are not started.
- **`INTERNET` permission therefore stays.** `feat.md` requires zero `INTERNET` for release, but the shipped OTA updater needs it. Dropping the permission before replacing the updater would silently break self-update, so both move together when Task 6 is picked up.
- **Fonts kept as Manrope/Cairo.** `feat.md` asks for Roboto Flex/Amiri; the bundled font assets were not available offline and shipping a font file nobody can verify is worse than keeping a font that already renders correctly in all three locales.
- **`audioplayers` kept over `just_audio`.** Same reasoning: swapping the adhan playback engine is a behavioural change to the feature the app exists for, and `audioplayers` already works. Revisit with Task 6.
- **No extra `permission_handler`.** `feat.md` lists it for the Alarm/Notification guides, but `geolocator` already owns the location permission flow; adding a second permission plugin for the same grant invites a disagreement between the two.
- **Location is resolved once, on Home.** Times and Qibla read coordinates off `HomeState` instead of calling `geolocator` again — a second `getCurrentPosition` means a second GPS round trip and a second permission prompt when the user opens a tab seconds after Home. `HomeState` gained `latitude`/`longitude` for this.
- **`PrayerKind` display names stay in `lib/l10n/enum_localization.dart`.** Unchanged from before, but now load-bearing for the Times table: the column headers need a localized, abbreviated prayer name, and a model cannot reach a `BuildContext`.
- **Times table abbreviates prayer names to three characters.** Five full names do not fit five times across a phone. The abbreviation is applied in the widget, not in the model, because the settings list needs the full name.
- **`intl`'s `TextDirection` is hidden wherever `dart:ui`'s is needed.** `package:intl/intl.dart` exports a `TextDirection` class that shadows `dart:ui`'s enum, so `TextDirection.rtl` stops resolving. Imported with `hide TextDirection` rather than aliased, because `DateFormat` is the only thing actually needed from `intl`.
- **`NavVisibilityScope` gained a notification-based `wrap()`.** `attachScroll` needs an owned `ScrollController` and a manual detach callback; Home and Settings use plain `ListView`s, so they use `wrap()`, which needs no `State` and disposes itself.
- **Scrolling up reveals the bar immediately, not at the top.** The first implementation keyed visibility off `offset > threshold` alone, which contradicted its own documentation and made scrolling up through a 31-row month feel broken.
- **Times paging shows the new month immediately and fills it in.** The computation is a few milliseconds; a full-screen spinner for that reads as a stutter.
- **Radii are tokens everywhere; `BlurSurface` no longer clamps.** The clamp was added because `BorderRadius.circular(double.infinity)` — the standard pill idiom — makes `RRect` scale radii against the box and assert inside the engine once an unbounded parent is hit-tested. Matching Walt exactly showed the clamp was treating a symptom: Walt has no clamp because Walt never passes `double.infinity`, it passes `AppRadius.pill`, and callers pass finite tokens like `AppRadius.xl`. Porting the geometry faithfully removed the need for the workaround, so `BlurSurface` now takes a finite `AppRadius` default and the `LayoutBuilder` is gone.
- **A `Text` as a direct child of a `Row` must be wrapped in `Flexible`.** This produced the real `RenderFlex overflowed ... on the right` on Home: a `Row` hands a direct `Text` child an *unbounded* main-axis width, so it laid out at the full intrinsic width of the sentence and painted past the card by exactly that difference. Every such row is now swept by `test/tab_layout_test.dart` across 360/388dp in all three locales.
- **A `MissingPluginException` for a newly added plugin means a stale native install, not a bad registration.** `flutter_compass` was verified present in the APK dex, in `GeneratedPluginRegistrant.java`, and in `.flutter-plugins-dependencies`, alongside 13 other plugins that all work. Hot restart runs new Dart against the *old* installed native library, so a plugin added after the last `flutter run` produces exactly this error. It needs `flutter clean` and a real reinstall.
- **Qibla uses `flutter_compass`.** `feat.md` requires a live needle; there was no sensor dependency in the project. The bearing maths is pure and unit-tested, and the screen degrades to a "no sensor" state on devices without a magnetometer.
- **Qibla distance switches from km to m below 100 km.** Matches what the app already does for sunrise/sunset magnitudes, so the two read alike.
- **Nav bar placed as `Scaffold.bottomNavigationBar`.** It needs `extendBody: true` on the `Scaffold` for the frosted pill to have anything to blur; placing it in `body` hands the pill the wrong constraints.
- **The floating nav bar is now a byte-for-byte port of Walt's**, modulo import paths. Same `AnimatedSwitcher` icons, same `secondaryContainer` selected pill with revealed label, same spatial spring, same selection haptic, same `FittedBox(scaleDown)` for narrow windows. Reproducing it verbatim is cheaper and more predictable than approximating it.
